# 高频问题应答手册（qa-playbook）

> 用法：命中手册问题的按标准口径作答（仍需结合知识库最新内容校验）；未命中问题走 SKILL.md 应答流程。

## 一、价值与可行性类

**Q：AI 到底能帮我们做什么？**
- 口径：从客户痛点清单里挑 1-2 个对号入座，禁止泛泛罗列功能
- 结构：结论（能解决 {痛点}）→ 例子（同行业场景）→ 边界（不能做什么）

**Q：别人家做成了吗？**
- 口径：只引用知识库/案例库中有出处的案例；无出处回答「目前库内没有可引用的同类案例，不建议对标，我们可以先小范围验证」
- 红线：禁止编造「某知名企业」案例

**Q：我们公司太小/太大，适合吗？**
- 口径按分层：30 人以下谈单点降本（一个场景、一周见效）；30-200 人谈标准分期；央国企谈战略 + 合规先行

## 二、成本与周期类

**Q：要花多少钱？**
- 口径：给区间不给点值，说明「取决于场景范围与部署方式」；引用方案文档中的 ROI 假设表；无方案依据时回答「需要 FDE 评估后给报价，我先帮您整理需求」

**Q：多久能上线？**
- 口径：试点场景 4-6 周起步口径（含数据准备）；明确「上线」定义（试点上线 ≠ 全公司推广）

**Q： ROI 怎么算？**
- 口径：工时节省 × 频率 × 时薪 的保守口径先行；提示所有假设写在方案里可复核

## 三、数据安全与合规类

**Q：我们的数据会不会泄露？**
- 口径：说明部署方式对应的数据边界（私有化 / 专有云 / API 脱敏）；引用企业库中的安全方案文档；不确定客户部署形态时先反问确认
- 红线：不替公司做安全承诺，最终以合同与安全白皮书为准

**Q：数据要出海/出境吗？**
- 口径：按企业库合规口径回答；无把握时明确「此问题需要合规团队书面确认」

## 四、落地与组织类

**Q：员工不会用 / 抵触怎么办？**
- 口径：培训分层（管理员 / 普通用户 / 高管）+ 标杆用户示范 + 把使用纳入流程而不是靠自觉；可引用培训讲义工具（TRAIN-ASM-01）说明我们提供配套培训

**Q：先从哪个部门开始？**
- 口径：选「痛点清晰 + 数据可用 + 负责人支持」三条件交集的部门；避免选「最痛但数据一团糟」的部门开局

**Q：项目失败 usually 因为什么？**
- 口径：一把手支持度衰减、数据质量不达标、场景选得过大、无验收标准；每条附一句预防措施

## 五、操作支持类

**Q：系统怎么用 / 报错了怎么办？**
- 口径：给具体步骤（编号列出）；查不到操作手册时说「我记录这个问题并同步 FDE，会在 X 内回复」；同类问题重复出现时提交知识缺口

## 应答自查清单（输出前过一遍）

1. 结论是否在第一句？
2. 每个事实性内容是否标注了来源（知识库 / 文档 / 通用实践）？
3. 是否按受众裁剪了详略？
4. 不确定的地方是否显式标注而不是回避？
5. 是否存在编造的数字、案例或承诺？
