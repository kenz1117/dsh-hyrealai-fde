# 企业问题 QA（Enterprise QA）

回答企业客户问题的纪律：**先检索、再分层、标注来源、承认不知道**。

## 何时使用

- 客户问「AI 能不能做 X」「这事怎么做」「别人家是怎么落的」
- 培训 / 汇报现场被提问，需要快速给出有依据的回答
- 客户员工反复问同类操作问题，需要标准化答案

## 应答流程（顺序固定，不可跳过检索）

1. **检索优先**：`search_knowledge` 查双源知识库（公共 + 企业库）；命中即以库内口径作答并标注来源
2. **补充上下文**：涉及具体客户时 `get_client` 看画像分层，用客户的行业与规模校准措辞；涉及项目状态时 `get_project`
3. **分层作答**：
   - 对管理层：结论先行 + 业务价值 + 风险，控制在 5 句话内
   - 对业务部门：场景化例子 + 对现有流程的改变点
   - 对执行层 / IT：具体操作步骤、前置条件、常见坑
4. **诚实兜底**：知识库未命中且超出常识范围时，明确说「暂无可靠依据」，给出替代路径（安排 FDE 跟进 / 提交知识缺口），不编造
5. **沉淀闭环**：发现知识库缺口时用 `submit_knowledge` 提交候选，避免同类问题反复答不上

## 回答结构模板

```
【结论】一句话直接回答
【依据】来自 {知识库名 / 文档标题} 的口径；或标注「基于通用实践，待与贵司数据验证」
【怎么做】1-3 步可执行建议（按受众裁剪详略）
【局限】这个答案不适用的情况 / 需要补充确认的信息
```

## Guardrails

- 禁止编造数据、案例、价格与承诺；引用数字必须来自知识库或客户自己的数据
- 涉密问题（薪酬、人事、客户名单、未公开财务）不展开，提示走正式渠道
- 同一问题对内对出口径一致；与已有交付物冲突时以交付物为准并提示 FDE 复核
- 回答末尾对不确定项显式标注，方便 FDE 快速复核
