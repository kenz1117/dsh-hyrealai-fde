# 成员 1444 能力素养诊断

口径为《AI-FDE 能力素养与评价体系白皮书》的 **1444 模型**：一核（客户价值交付）· 四力（素养层）· 四域（能力层 16 项子能力）· 四阶（L1—L4，系统另设入门档 L0）。旧「12 维」记录只作存量数据回退展示，不得按新口径重算或改写。

## 何时使用

- 评估某位成员当前能力级别与素养状态
- 基于评估结果给出发展计划
- 对比历史评估，追踪缺口改善/持平/倒退

## 口径要点

- **四域 16 项子能力**（1—5 整数分：1=未站稳最低锚点，2—5=稳定达到第 1—4 级锚点）：业务认知 B1—B4、场景工程 S1—S4、AI 技术 T1—T4、交付保障 D1—D4，每项有四级行为锚点
- **四力素养**（1 有意识 / 2 成习惯 / 3 成本能）：探索力、融合力、专注力、担当力；既是定级门槛，也按线性折算（每项满分 5 分）计入综合分
- **综合分** = 16 项子能力总分（满分 80）＋ 四力素养分（满分 20）
- **定级**（综合分 + 域结构 + 素养门槛三者同时满足）：
  - L0 实习场景工程师 ≥40 分（无域与素养门槛）；L1 助理场景工程师 ≥52 分（任一域≥3.0）；L2 场景工程师 ≥63 分（场景工程≥3.5 且另有任一域≥3.0）；L3 场景专家 ≥78 分（3 域≥4.0 且场景工程≥4.5）；L4 首席场景官 ≥88 分（四域≥4.5 且场景工程、交付保障≥4.8）
- **边界带**：综合分距上/下定级线 ≤2 分时，结论注明边界（如「L1↔L2 边界」），不说成定论
- **评分就高原则**：两个档位间拿不准时取较高档；更高级别证据缺失只封顶，不拉低已展现档位
- **出身路径**（技术出身 / 业务出身 / 未定）：仅首次评估对单一域放宽 0.3 分（技术出身放宽业务认知域，业务出身放宽 AI 技术域）
- **担当力红线一票否决**：测评作弊或证据造假、违反客户保密义务或数据安全规定、在 AI 应用中故意隐瞒重大风险 → 直接不定级

## 执行步骤

1. 先用 `list_members` 唯一定位成员；无法定位或多个候选时用 `ask_user` 让用户选择，禁止猜测
2. 上下文组装由 `run_member_diagnostic` 内部完成（等价于 `run_tool` + `toolCode: "MEMBER-DIAG-12"`：成员档案 + 真实行为证据快照 + 上次缺口追踪）；单独调用它只返回组装后的提示词文本，不产生评分
3. `run_member_diagnostic` 传入 `memberId` 与 `action=start`，把返回的 `assistantMessage` **原样展示**给用户，然后停止并等待回答
4. 每轮把完整访谈记录放进 `messages`（`[{role,content}]`），`action=reply` 推进下一轮
5. 模型输出 `diagnostic_scores` JSON 后即进入待确认状态：展示四域均分、综合分、定级结论与理由，请用户明确确认
6. 仅在用户明确确认后调用 `action=confirm`，同时回传 `confirmed=true`、`scores`（16 项子能力）、`literacies`（4 项素养）、`track`、`redline`/`redlineNote`、`evidence`（各项评分依据）、`conclusions`

## Guardrails

- 语气全程鼓励式：先肯定再追问，禁止压迫感措辞；对方不想聊时立即收束进入总结——让对方测完比评分精确更重要
- 分数必须来自真实证据，禁止编造；每个分数尽量对应一个具体事例，拿不准时按就高原则处理
- 必须引用真实行为数据作为客观佐证；自述与数据明显矛盾时在依据中标注分歧
- 禁止跳过访谈直接给结论，禁止未确认就落库
- 系统行为数据仅是佐证，不替代行为锚点判定
