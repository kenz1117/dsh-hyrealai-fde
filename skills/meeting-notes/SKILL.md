# 会议纪要（Meeting Notes）

纪律：**纪要是承诺清单，不是聊天记录**。每个行动项必须有责任人和期限，缺一个就标问号逼问，不允许「大家看着办」。

## 何时使用

- 客户现场会议（调研访谈 / 方案汇报 / 周例会 / 培训现场）结束后整理纪要
- FDE 提供口述速记、录音转写片段或零散要点，需要结构化
- 历史纪要散落多份，需要合并去重成单一事实来源

## 工作方式

1. **先问三要素**：开始整理前确认「会议时间 / 参会人与角色 / 会议目的」；缺失时用 `ask_user` 向 FDE 补齐，不要猜
2. **只整理三类内容**：决议（定了什么）、行动项（谁在何时做什么）、待确认问题（没定但必须定的）；过程性讨论一律丢弃
3. **行动项五要素**：事项 / 责任人（具体到人名）/ 期限（具体到日）/ 验收标准 / 依赖项；任何一项缺失就用 `ask_user` 补问
4. **归档建议**：整理完成后提示 FDE 确认；若为项目正式会议，可用 `generate_deliverable`（stage=管理）沉淀为管理阶段交付物
5. **对比前情**：涉及项目进展时先 `get_project` 看当前阶段与里程碑，纪要中的进展表述要与项目档案一致，冲突处标注

## 纪要结构模板（正文精简版）

```
【会议】{主题}（{日期}，{参会人}）
【结论】本次会议最重要的 1-3 个决定，每条一句话
【行动项】
| # | 事项 | 责任人 | 期限 | 验收标准 | 状态 |
【待确认】会上未决、需要下次带答案的问题清单
【风险】会上暴露的新风险或变化（含一把手态度、预算变化等信号）
```

## Guardrails

- 不编造会议内容；速记含糊处写「{原文模糊}，待与 {谁} 确认」而不是脑补
- 责任人必须是会上真实提到的人；速记只说「他们部门」时标注「责任部门待落实到人」
- 涉密内容（报价底线、内部分歧）不出现在纪要正文，提示 FDE 单独记录
- 纪要草稿必须经 FDE 审核后才能发客户；发送口径与系统项目档案一致
