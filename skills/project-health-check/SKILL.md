# 项目健康检查（Project Health Check）

纪律：**预警必须带干预动作**。只报「有问题」不给「怎么办」的检查等于没检查。

## 何时使用

- 定期（双周 / 月度）巡检名下项目，提前发现烂尾苗头
- 项目数据异常（健康分下降、里程碑超期）需要定位原因
- 决定资源投向：多个项目谁优先救

## 工作方式（用系统数据，不用印象分）

1. **读数**：`get_project` 读健康分、当前阶段、里程碑完成情况；批量巡检时逐项目读取
2. **五项信号检查**（每项判「正常 / 观察 / 预警」）：
   - 节奏：最近一次里程碑更新距今多久（>2 周无更新即观察，>4 周即预警）
   - 进度：里程碑是否超期、阶段停留时长是否异常
   - 交付：上一阶段交付物是否齐备（`get_upstream_deliverables`）
   - 组织：近期会议纪要中一把手是否露面、行动项是否反复延期
   - 数据：业务指标是否连续两期无变化（推广期停滞信号）
3. **分级**：全部正常=绿；任一「观察」=黄；任一「预警」=红
4. **干预建议**：黄灯给自查动作；红灯给升级动作（约谈谁 / 调整什么 / 什么期限）
5. **留痕**：检查结论提示 FDE 确认后可整理进进展报告（progress-report）或管理阶段交付物

## 健康报告结构

```
【健康评级】绿 / 黄 / 红（一句话理由）
【信号清单】
| 检查项 | 结论 | 证据（数据/出处） |
【根因判断】{节奏 / 数据 / 组织 / 范围 四类归因，可多选}
【干预建议】
- 黄灯：{FDE 可自行执行的动作 + 检查期限}
- 红灯：{升级对象 + 期望动作 + 截止时间}
```

## Guardrails

- 每个信号必须引用系统数据或纪要出处；无数据支撑的直觉判断单独标注「待验证」
- 不直接改写项目档案与健康分（系统不提供该项目写工具）；建议由 FDE 确认后人工维护
- 红灯升级建议对事不对人：写行为与影响，不做人身评价
- 批量巡检时按红→黄→绿排序输出，红灯项目置顶
