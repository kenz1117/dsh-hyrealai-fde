# 培训计划表与实操任务卡设计（training-kit）

> 用法：排期用计划表；设计学员实练环节用任务卡；课堂突发情况查控场技巧。

## 一、培训计划表模板（按部门滚动推广）

```markdown
# {客户名} AI 应用推广培训计划（{月份}）

| 场次 | 部门 | 受众 | 人数 | 时长 | 内容模块 | 前置准备 | 时间 |
|------|------|------|------|------|----------|----------|------|
| 1 | {试点部门} | 一线用户 | | 60min | 演示+实练 | 演示账号×N、样例数据 | |
| 2 | {试点部门} | 部门骨干 | | 90min | 上述+答疑职责 | 常见问题手册 | |
| 3 | 管理层 | 部门负责人 | | 30min | 价值+进度 | 月度数据截图 | |

## 每场结束标准（当场验收）
- 一线用户场：≥70% 学员现场完成 1 个真实任务
- 骨干场：每人能回答 Top 5 高频问题
- 管理层场：确认下期推广部门与时间
```

## 二、实操任务卡设计（实练环节核心）

每张任务卡只有一个任务，控制在 10 分钟内：

```markdown
## 任务卡 {编号}：{任务名（动词开头）}
- 你将做到：{完成的标志，如"生成一份周报草稿"}
- 步骤：1) … 2) … 3) …（截图逐步标注）
- 卡住了怎么办：{每步最常见的失败 + 一句话解法}
- 完成后Extra：{可选进阶，给快学员}
```

设计规则：
1. 用学员部门的真实素材，不用「张三李四」假数据
2. 每张卡配「卡住怎么办」，避免全场举手等待
3. 快慢分组：完成快的学员拿进阶卡或当小老师

## 三、课堂控场技巧

| 情况 | 处理 |
|------|------|
| 环境故障（登不上/加载慢） | 立即切录屏演示继续流程；安排专人现场修，不占课堂时间 |
| 学员「这东西不准」 | 收集原话记入待办，回应「现场记录，X 个工作日回复」；不当场辩解 |
| 学员担心被取代 | 用统一口径：「把重复劳动交出去，把判断留给人」；举部门内真实变化 |
| 高频问题超 3 个 | 当场记录，培训后 48h 内出 FAQ 提交知识库 |
| 进度严重超时 | 砍进阶内容保「完成 1 个真实任务」底线；剩余内容转部门骨干场 |

## 四、培训效果回访（培训后 1-2 周）

1. 使用数据：部门活跃人数 / 任务完成量（progress-report 口径取数）
2. 访谈 2-3 名学员：最常用功能 / 最卡的地方
3. 输出：一份两页回访纪要（meeting-notes 模板）+ 知识库更新（submit_knowledge）
4. 判断：达标→约下个部门排期；不达标→按项目健康检查（project-health-check）数据信号处理
