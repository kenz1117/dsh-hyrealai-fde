# 进展汇报（Progress Report）

纪律：**汇报里每个数字都要有出处**。取不到的数写「数据源待接入」，不编约数。

## 何时使用

- 每周 / 每月例行的项目进展报告
- 向客户高管做阶段性汇报（月度经营会、 Steering Committee）
- 向自己公司汇报驻场动态与风险预警

## 工作方式（先取数，再成文）

1. **项目底盘**：`get_project` 读当前阶段、健康分、里程碑完成度——进展表述必须与里程碑对得上
2. **业务数据**：`query_business_data` 取本期关键指标（使用量、效率变化等）；取不到的指标列为「数据源待接入」，不估算
3. **上期对账**：上期报告的「下期计划」逐条对账：完成 / 延期（原因） / 砍掉（原因）
4. **分口径成文**：
   - 对客户高管：价值与数据先行，技术细节收进附录
   - 对公司内部：风险与客户关系信号先行，数据其次
5. **正式交付**：作为管理阶段正式报告输出时用 `generate_deliverable`（stage=管理）留存版本

## 报告结构模板（正文精简版）

```
【本期结论】三句话：进展到哪 / 数据表现如何 / 最大的一个风险或请求
【进展与数据】
- 里程碑：{X/Y 完成，当前阶段}（与项目档案一致）
- 关键指标：| 指标 | 上期 | 本期 | 变化 | 出处 |
- 本期完成事项：按「客户价值」排序，不按工作量排序
【下期计划】3-5 条，每条可验证
【需协调事项】需要客户或公司拍板的事（写清决策人 + 期望决策时间）
```

## Guardrails

- 数字必须有出处（业务数据 / 里程碑 / 上期报告），引用外部信息标注来源
- 坏消息不隐瞒：延期、数据不达标、客户态度变化必须写进风险，并给对策
- 「需协调事项」必须具体到决策人和时间，不写「希望领导重视」这类无法行动的话
- 报告草稿经 FDE 审核后才能提交；对外口径与项目档案（healthScore / 里程碑）一致
