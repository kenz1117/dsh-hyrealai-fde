# 进展报告模板与坏消息表达法（report-kit）

> 用法：按报告对象选模板；坏消息表达法用于把风险写清楚而不引发恐慌。

## 一、周报模板（对客户项目组，1 页内）

```markdown
# {项目名} 周报（{日期区间}）

## 本周结论（3 句话）
1. 进展：{如：试点场景上线，进入推广期}
2. 数据：{如：周活跃 {N} 人，报表耗时从 2 天降至 2 小时（出处：{系统}）}
3. 风险/请求：{最大的一个}

## 里程碑看板
| 里程碑 | 计划 | 实际 | 状态 |
|--------|------|------|------|
（与项目档案九阶段里程碑一致）

## 本周完成 / 下周计划
- 完成：{按客户价值排序}
- 计划：{3-5 条，每条可验证}

## 需协调
| 事项 | 决策人 | 期望决策时间 |
```

## 二、月报 / 高管汇报模板（对客户管理层）

```markdown
# {客户名} AI 落地月度汇报（{月份}）

## 一页结论
- 价值兑现：{累计节省工时/成本，标注假设与出处}
- 推广进度：{覆盖部门/人数，环比}
- 下月重点：{1-3 条}
- 需要您的支持：{具体到决策事项与时间}

## 数据明细（附录）
| 指标 | 上月 | 本月 | 变化 | 出处 |
```

高管版原则：第一屏只有结论和请求；数据明细全部放附录。

## 三、对内汇报模板（给自己公司）

```markdown
# 驻场动态（{客户名}，{日期}）
- 项目状态：{阶段 + 健康分解读}
- 客户关系信号：{一把手关注度 / 中层配合度 / 新增接触点}
- 风险与商机：{延期风险 / 新场景机会 / 续约信号}
- 需要公司支持：{资源 / 专家 / 决策}
```

## 四、坏消息表达法（写清事实，不引发恐慌）

公式：**事实 + 影响 + 已做什么 + 需要什么**

| 场景 | 差写法 | 好写法 |
|------|--------|--------|
| 里程碑延期 | 「进度有点慢」 | 「{里程碑} 原计划 {日期}，因 {原因} 预计延至 {新日期}；已 {补救动作}；需要 {支持}」 |
| 数据不达标 | 「效果一般」 | 「{指标} 本期 {X}，未达目标 {Y}；差距主因 {Z}；下期动作 {动作}」 |
| 客户态度变化 | 「客户不太满意」 | 「{部门} 对 {场景} 使用率降至 {X}%；已访谈 {人} 定位原因为 {原因}；建议 {动作}」 |
| 需要加资源 | 「人手不够」 | 「推广期需覆盖 {N} 个部门，当前 {M} 人；建议 {方案A/B}，{日期} 前确认」 |

## 五、自查清单

1. 每个数字是否有出处？
2. 上期计划是否逐条对账？
3. 坏消息是否按「事实+影响+对策+请求」写全？
4. 需协调事项是否具体到人和时间？
5. 对客户与对内的两份口径是否一致（详略不同、事实相同）？
