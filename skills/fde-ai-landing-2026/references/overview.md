## 1. 结构 (Structural)

### 类型
实操手册 + 路径研究 + 组织方法论的混合体。五份材料围绕同一个问题从五个切面展开：**AI 怎样在真实企业里产生价值，而不是停在 PPT 上**。

### 一句话主旨
AI 落地的瓶颈已从模型能力转移到「最后一公里」，解法是一套可复制、可考核、可沉淀的驻场工程方法（FDE）+ 从个人提效走向组织能力的跃迁体系 + 以事实与候选为核心的知识治理机制。

### 骨架（五个切面及其关系）

1. **为什么**（制造业 FDE 白皮书 1–2 章、驻场指南 1 章）：GenAI 鸿沟——300–400 亿美元投入、95% 组织无可衡量损益；瓶颈是「学习鸿沟」而非基础设施；制造业现场（OT/IT 异构、数据非标、老师傅手感）决定了必须驻场。
2. **谁来干**（两份大任白皮书）：FDE 岗位界定——三栖能力模型（20% 销售 / 30% 产品 / 50% 工程）、真 FDE 五条鉴别标准、FDE+FDR 协同（交付之后的「下半场」）、三级能力进阶（L1 应用级 / L2 技能级 / L3 架构级，靠作品不靠笔试）。
3. **怎么干（单项目）**（驻场指南 2–11 章）：「四重九式」——进场期（进场准备/驻场观察）、共创期（需求确认/方案共建/原型验证）、运营期（交付运营/协同开发）、沉淀期（复盘沉淀/规模复制），每式有目标/动作/交付项/工具表/质量门禁；SLP 方法（Scene-Link-Pilot）是制造业场景的浓缩版落地路径。
4. **怎么干（组织级）**（提效框架 2.0 + 阿里云手册）：五层级成熟度（L1 战略对齐→L5 智能原生）+ 两条横切轴（数据基础、治理安全）；L3→L4 鸿沟与 90 天 Playbook；阿里云三案例呈现「超级个体→数字员工→云上 Scrum」的组织演进，以及上下文资产/可靠交付四环节（项目理解、需求理解、可靠编码、线上排障）。
5. **怎么守住**（ANC 架构 + 阿里云挑战章）：知识不回流、状态混乱、无人治理是组织级 AI 的隐形杀手。ANC 给出确定性治理架构——四种数据分类绝不互相冒充（Blob/Event/Candidate/Git Vault）、知识飞轮八步闭环「每晚只提出候选，不改写公司真相」、Git 为唯一真相源。

**论点之间的关系**：递进 + 互补。1 是问题诊断，2–3 是项目级解法（人 + 流程），4 是组织级解法（成熟度 + 平台 + 组织演进），5 是治理级解法（让经验变成可审计的公司资产）。五者构成「诊断 → 派人 → 干项目 → 建组织 → 立治理」的完整链条。

### 作者要解决的核心问题
AI 项目为什么普遍「上线即静止、POC 后被放弃」？如何在客户现场/企业内部把 AI 从演示变成被真正使用、持续进化、可复制推广的生产系统，并让过程中产生的经验沉淀为组织资产而非随人流失。

## 2. 解释 (Interpretive)

### 关键术语（作者本人的用法）

| 术语 | 作者的定义 | 和常识用法的差异 |
|---|---|---|
| FDE（前沿部署工程师） | 驻扎客户现场、对业务价值落地负全责的复合岗位，独立完成「需求挖掘→部署→运营→价值验证→沉淀」全链路 | 不是「驻场实施工程师」或「会写代码的售前」；七成以上时间在现场开发调试，有需求决策权，对结果兜底 |
| 四重九式 | 驻场服务的专业流水线：九个节点按四重（进场/共创/运营/沉淀）推进，每式有质量门禁 | 不是项目管理阶段划分，而是「有门禁、有交付、有沉淀」的作业标准；首尾相衔成循环 |
| 质量门禁 | 每一式结束时的强制验收条件（如「验收标准书面化」「痛点逐条量化」），不过门禁不得进入下一式 | 不是柔性 checklist，而是阻断性的关卡 |
| 双闭环 | 服务闭环（查对→执行→记录→优化，对客户）+ 能力闭环（实践→复盘→沉淀→晋级，对组织） | 两个闭环同时运行，个人沉淀汇入组织资产库 |
| FDR | FDE 的「下半场」：技术反馈平台，承接交付后的模型漂移、返修与迭代 | 不是运维；是「一锤子买卖」困局的解药，让 AI 随现场持续进化 |
| SLP 方法 | Scene-Link-Pilot：场景锁定（小、可度量、有权限）→ 跨界链接（工艺工程师/操作员/管理者，隐性知识显性化）→ 试点验证（2–4 周，现场演示，数据说话） | 不是 PoC 方法论——强调「现场本位」倒转「技术本位」：模型与现场不符，错的是模型 |
| 五层蛋糕 / 三体架构 | 中国式本体论：五层（主体价值观→基础设施台）+ 三体（主体人/数体物/智体事） | 比 Palantir Ontology 多建模了「价值与规则」层——技术驱动型 AI 项目缺失的前提 |
| 五层级框架 | 企业 AI 提效五级：战略对齐→认知普及→个人提效→组织提效→智能原生，配 12 题诊断 | 核心不是分级而是「L3→L4 鸿沟」：个人省时间 ≠ 组织提效 |
| 云上 Scrum | 数字员工小队按共同工程协议自组织交付，人只负责目标与验收 | 不是敏捷开发改名——排期/日会/总结会全部消失，因为 Agent 来活即起线程、卡点随时沟通、任务自带反思 |
| 上下文资产 | 产品/技术/设计文档 + 真实工程 + 测试证据，每次任务由 Agent 按需读取 | 不是知识库文档堆——是「一个需求、一组事实」，验证发现的新事实回写沉淀 |
| 知识飞轮 / 候选账本 | CAPTURE→…→USE+EVAL 八步闭环；自动化只到「提出候选」，合并必须人工审批 | 关键在「不改写公司真相」：候选绑定来源哈希，可拒绝、可回滚 |
| 智能积木 | 一次优化、多域复用的能力单元，新场景适配成本降至全新设计的约 20% | 不是组件库——是从失败轨迹 Skill 化而来（手脚 Loop） |

### 核心命题（用自己的话）

1. AI 落地失败极少败于模型不够强，多败于最后一公里断裂：需求被误读、数据不可用、系统接不进、现场没人管、价值没人算。
2. 最后一公里必须有人驻在现场走完——FDE 模式（驻场交付、对结果负责）已被市场与资本验证。
3. 真 FDE 是复合能力（工程打底、业务加码、产品点睛），不是换皮的实施/售前岗位。
4. 驻场服务可以也应该从个人经验升级为有门禁、有工具表、有沉淀的标准作业体系。
5. 交付不是终点：模型随工艺/订单/设备老化而漂移，没有「下半场」（FDR）效果必然衰减。
6. 制造业落地要「现场本位」：选小场景、让老师傅手感变算法输入、2–4 周用数据说话。
7. 个人提效 ≠ 组织提效；L3→L4 的鸿沟靠「选对切入点 + 建平台而非单点 + 组织与 KPI 同步调整」跨越。
8. AI 必须成为流程默认路径、以业务指标为唯一验收，才算组织级落地。
9. 研发范式的重心从「写代码」迁移到「问题定义、上下文组织、边界设计、验证」；AI 输出稳定性取决于基础设施是否 AI 友好。
10. 数字员工组织演进有清晰路径：超级个体（产能锁在个人会话）→ 数字员工（产能团队化但人肉调度）→ 云上 Scrum（闭环自组织，人负责 Loop 维护与寻找真需求）。
11. 组织级 AI 的前提是数据基础与治理安全同步升级——数据中台是 L4 入场券而非可选项。
12. 经验必须经过「候选→验证→审批→合并→使用→评估」才能成为公司资产；自动化到提案为止，真相只能由人改写。
13. 知识不沉淀 = 人走经验走；沉淀必须是可复用资产（场景卡、话术、清单、负面清单、Skill），而非项目文档归档。

### 论证链
行业数据（MIT NANDA 95% / Gartner 30% / 薪酬与岗位增速）确立「落地是瓶颈」→ Palantir 二十年 + 巨头军备竞赛证明「驻场交付」模式成立 → 中国本土案例（八大制造业场景量化数据：产能 +5% 年增收 10 亿、设计周期 180→7 天、60 组数据月省电费 8 万）证明「小场景驻场」在中国可行且普惠 → 组织级框架（五层级 + 云上 Scrum 案例数据：交付周期减半、缺陷率降 70%）说明单点成功如何放大 → 治理架构（ANC 四类数据 / 知识飞轮 / 阿里云 Guardrail）回答「放大之后如何不失序」。

## 3. 批判 (Critical) ★

### 作者的时代局限
- 数据与案例几乎全部来自 2025–2026 年的高峰期，FDE 薪酬/岗位增速处于爆发泡沫段，「729% 增长」类数据隐含低基数效应，不宜线性外推。
- 模型能力演进极快，部分「必须驻场人工做」的论断（如现场排障、需求澄清）可能随 Agent 自主性提升被部分消解——白皮书自己也承认这是动态边界。
- 政策红利（人工智能+行动）是重要推力，但白皮书对政策退坡后的商业自持性论证不足。

### 作者的立场盲点
- 大任智库/场景学社本身是 FDE 培训认证的供给方（教练营、认证、白皮书三件套互相引流），存在「卖水人写水源报告」的利益相关，ROI 案例多为服务商口径，缺甲方独立审计。
- 制造业大企业案例浓重，对中小企业「付不起驻场费」的现实仅以「轻驻场+远程陪跑」一笔带过，成本账算得不够狠。
- ANC 架构是单人/小团队治理视角的理想化设计（每晚候选、Git 真相源），在多利益方、高合规企业环境的落地成本未论证。
- 阿里云案例的资源密度（云上运行时、内部平台、集团基建）中小组织不可复制，手册对此自觉但读者未必。

### 未被证明的假设
- 假设「把隐性知识翻译成参数」总是可行——老师傅手感未必都能显性化，白皮书未讨论翻译失败的模式。
- 假设客户愿意被「门禁」管理——甲方按里程碑付款，门禁增加了乙方自缚的合同风险，实践中未必可执行。
- 假设组织愿意同步改 KPI——这是 L4 成败关键，但也是最难的条件，框架把它列为动作而非前提审查。
- 假设 12 题诊断的分值区间能可靠区分层级——无信效度验证，本质是启发式自查表。

### 最强反对意见
「FDE 是把高级外包包装成了新叙事：驻场 + 对结果负责 = 定制化外包的定义。Palantir 的成功靠的是平台本体论的可复用性，而非驻场本身；没有平台资产沉淀的驻场，正是 Bob McGrew 说的『退化为定制化外包』。中国 FDE 浪潮里，多数服务商恰恰缺的正是产品回流通道。」——五条鉴别标准自己承认了这一点，但白皮书未回答「没有 Palantir 级平台的中国服务商如何避免这个陷阱」。

> **以上批判会直接成为下游 skill 的 Boundary (B) 字段来源**
